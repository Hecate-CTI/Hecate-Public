## LEARN: Prepare the Hunt

### Hypothesis Statement

Adversaries use malformed Base64 strings with stray padding characters in HTTP Authorization headers, JWTs, or SAML artifacts to trigger heap corruption in OpenJDK's AVX-512 decoder intrinsic, achieving pre-authentication remote code execution on enterprise Java applications running on Ice Lake+ or Zen 4+ CPUs

### Threat Context

Source CTI:

> Java4Shell / Java2Shell (CVE-2026-114938) — Calif disclosure (17 Nov 2026)

Critical memory-corruption vulnerability in OpenJDK HotSpot's x86-64 AVX-512 VBMI Base64 decoder intrinsic (java.util.Base64.Decoder). CVSS 4.0 9.2 (Calif) / CVSS 3.1 8.1 High with high attack complexity (Oracle).

Trigger: malformed Base64 with a stray padding character, e.g. 64×"A" + "=" (OpenJDK 17 uses 128×"A" + "="). The native tail handler computes a negative output length; BZHI turns that into an all-ones store mask; VMOVDQU8 writes 64 bytes starting mid-buffer (62 bytes past the logical end). Java then throws IllegalArgumentException — the HTTP response (often 401) does not indicate heap corruption already occurred.

Affected: OpenJDK 17.0.6+ (branches 17/21/25/27) and derivatives (Temurin, Corretto, Azul, Liberica, SapMachine, Red Hat, Oracle Java SE/GraalVM). Not: standard Java 8/11, OpenJ9, ARM64. Hardware gate: avx512f + avx512bw + avx512vbmi + bmi2 (Ice Lake+/Zen 4+).

Pre-auth RCE demonstrated (default configs): Keycloak, Atlassian Jira, Atlassian Confluence, JFrog Artifactory, Jenkins, PingFederate.
Post-auth RCE: Apache Kafka Broker, Apache Solr, Elasticsearch, Gerrit, Netflix Spinnaker.
Also: Spring Boot / Struts samples; client-side TLS path (Java client to malicious server).

Attack surface: any attacker-controlled Base64 before auth — HTTP Basic Authorization headers, JWTs, SAML artifacts, file uploads, network messages. MIME decoder (Base64.getMimeDecoder()) reportedly bypasses the vulnerable path; basic/URL decoders are in scope.

Mitigations: patch to 17[.]0[.]21[.]1 / 21[.]0[.]13[.]1 / 25[.]0[.]5[.]1 / 27[.]0[.]1[.]1 (restart process); interim -XX:-UseBASE64Intrinsics or (x86-64 only) -XX:UseAVX=2.

Detection angles for hunters: HTTP requests with malformed Base64 padding patterns in Authorization/Basic, JWT/SAML, or upload bodies; bursts of IllegalArgumentException from Base64 decode in app/JVM logs; JVM hs_err / SIGSEGV / GC crashes after decode exceptions; unexpected child processes from Java services (Keycloak/Jira/Confluence/Jenkins/Artifactory); recon User-Agents referencing java4shell; inventory of JVM flags UseBASE64Intrinsics/UseAVX on AVX-512 hosts.

### Justification

The Calif disclosure demonstrates pre-auth RCE against default configurations of Keycloak, Atlassian Jira, Atlassian Confluence, JFrog Artifactory, Jenkins, and PingFederate. The vulnerability is triggered by attacker-controlled Base64 before authentication in HTTP Basic Authorization headers, JWTs, and SAML artifacts. The heap corruption occurs silently before the application throws IllegalArgumentException, meaning standard HTTP error responses (often 401) do not indicate compromise. This creates a pre-authentication attack surface against critical enterprise identity and collaboration platforms, with the hardware gate (AVX-512 VBMI on Ice Lake+/Zen 4+) limiting but not eliminating exposure in modern server deployments.
