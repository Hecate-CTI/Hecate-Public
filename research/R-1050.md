## 1. System Research: How It Works

### Summary
MISP is a threat intelligence platform that synchronizes data, including sightings, between server instances. The vulnerability CVE-2026-135243 allows an attacker to bypass authorization checks during this synchronization process, causing sightings from untrusted sources to be incorrectly bound to private events.

### Key Findings
- The vulnerability is an Insecure Direct Object Reference (IDOR) / authorization bypass in MISP versions prior to 2.5.52, specifically affecting the handling of sightings during server synchronization and bulk operations.
- Exploitation allows a remote attacker with access to a synchronized instance to inject sightings into private events that should not be visible to them, effectively leaking sensitive threat intelligence context.
- The fix was published by ENISA in November 2026, assigning the issue a CVSS v4.0 base score of 5.3 (Medium), indicating it requires specific synchronization conditions rather than trivial remote execution.
- Public proof-of-concept repositories exist demonstrating the vulnerability via HTTP POST requests to a '/check' endpoint within a lab environment, though no verified in-the-wild exploitation has been confirmed as of November 23, 2026.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
CVE-2026-135243 represents an authorization bypass vulnerability in MISP versions prior to 2.5.52, allowing attackers to pull sightings for events not shared with their organization during server synchronization. This flaw enables the injection of sightings into private events by exploiting a lack of sharing checks and insufficient validation of attributes referenced in bulk save operations.

### Key Findings
- CVE-2026-135243 is an Insecure Direct Object Reference (IDOR) and authorization bypass vulnerability affecting MISP <2.5.52, with a CVSS Base Score of 5.3 (Medium).
- The vulnerability arises because the sighting pull mechanism executes with elevated privileges and the bulk save functionality fails to enforce that attributes belong to the specific event specified in the URL.
- A public GitHub repository by user 'googlesky' provides a Proof of Concept, including an exploit script and lab scripts, though it has not been verified as a working weaponized exploit.
- There is currently no evidence of exploitation in the wild; no public nuclei templates are indexed, and no attack traffic was recorded by OffSeq Mirage sensors as of November 23, 2026.
- The vulnerability was reported by ENISA and fixed in MISP version 2.5.52, which introduced a 'syncedWithServer' guard to prevent bound sightings on vulnerable instances.

## 5. Research Synthesis

### Executive Summary
A public PoC repository (googlesky/CVE-2026-135243) documents an IDOR/authorization-bypass in MISP <2.5.52 whereby the sighting-pull sync path executes without enforcing event-level sharing checks, permitting a low-privileged authenticated peer on a synchronized instance to inject sightings into private events and infer their existence. OSV.dev confirms the advisory (CVSS 4.0 base 5.3 Medium); EPSS scores exploitation probability at 0.45% (39.8th percentile) with no VulnCheck KEV listing and no verified in-the-wild exploitation as of the report date, placing this firmly in the 'public PoC, unconfirmed exploitation' tier. Hunt value lies in detecting unauthorized cross-organization sighting injection and anomalous sync-peer API activity against MISP infrastructure, not in host-level execution chains.

### Recommended Hypothesis
> Adversaries use the MISP sighting-pull synchronization endpoint (lacking event-sharing validation) to inject sightings into private events on a target MISP instance, with the goal of inferring the existence and context of threat intelligence that was never shared with their organization, targeting MISP deployments running versions prior to 2.5.52 that maintain active server-sync relationships with untrusted or compromised peer instances.

### Gaps Identified
- MISP application-layer audit logs for sighting-pull and bulk-save API calls (specifically the syncedWithServer guard path) are the primary evidence source for this vulnerability class; if these logs are not ingested into the SIEM — or if MISP's own audit trail does not record the originating sync-peer identity alongside each sighting write — the injection action is unobservable from external telemetry alone, leaving a critical blind spot regardless of network or host sensor coverage.
- The vulnerability's exploitation surface is entirely within authenticated HTTPS API traffic between MISP sync peers; without TLS inspection or MISP-native request logging that captures the full POST body to the sighting-pull endpoint (including event UUID and attribute references), network-layer sensors cannot distinguish a legitimate sync operation from a malicious one that references out-of-scope private events, rendering payload-level detection infeasible from perimeter telemetry.
- The PoC lab uses a containerized environment (run-lab.sh, sig-vuln/sig-fixed hostnames) and a Python exploit script against a /check HTTP wrapper, but the actual MISP production attack path targets native sync API routes; if the adopter's MISP instance version, patch level, and sync-peer trust relationships are not inventoried and confirmed, it is unknown whether the vulnerable code path is reachable in the production environment — a prerequisite gap that prevents scoping the hunt to at-risk hosts.
