## 1. System Research: How It Works

### Summary
The subject system is an iQOO Neo5活力版 (PD2118/V2118A) device running Linux kernel 4.19.152-perf+ and Android 14/OriginOS 4, utilizing ARM64 architecture with a futex priority-inheritance mechanism. This mechanism is vulnerable to a use-after-free condition in the rtmutex path, which allows an unprivileged local user to execute arbitrary code and escalate privileges to root via a crafted exploit chain involving stack frame exploitation and fake lock structures.

### Key Findings
- The vulnerability CVE-2026-43499 is a high-severity (CVSS 7.8) use-after-free bug in the Linux kernel's futex priority-inheritance path, specifically within the remove_waiter() function, allowing local privilege escalation without special capabilities.
- Exploit artifacts include a precompiled PIE binary named 'ghostlock_pd2118' and an embedded 'su_daemon_aarch64_pie', which are pushed to /data/local/tmp/ via ADB to establish a root shell on the target device.
- Mitigation guidance suggests that temporarily blocking priority-inheritance futex operations via seccomp rules can reduce exposure in container environments, though this may disrupt legitimate workloads relying on these operations.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
GhostLock (CVE-2026-43499) is a local privilege escalation exploit targeting a use-after-free vulnerability in the Linux kernel's futex priority-inheritance code, allowing unprivileged users to gain root access by manipulating stack frames via deadlock conditions. The technique leverages a 15-year-old rtmutex flaw to escape container restrictions and achieve full system control on affected kernels since 2011.

### Key Findings
- The vulnerability is a use-after-free (UAF) in the Linux kernel's real-time mutex (rtmutex) priority-inheritance logic, specifically involving stale pointers into freed kernel stack frames.
- Exploitation requires local access; an attacker arranges three futexes and coordinated threads into a priority-inversion deadlock to trigger the UAF primitive.
- The attack chain involves spraying chosen bytes onto the freed stack via a forged waiter structure, leading to arbitrary code execution or root privilege escalation.
- Public PoCs exist for specific Android devices like the iQOO Neo5 (PD2118C) with kernel 4.19.152-perf+, demonstrating real-world applicability on mobile Linux variants.
- Patch availability is confirmed for AlmaLinux releases 8, 9, and 10, indicating that the exploit affects mainstream Linux distributions dating back to 2011.

## 5. Research Synthesis

### Executive Summary
CVE-2026-43499 is a public GitHub PoC for a Linux kernel futex priority-inheritance use-after-free vulnerability enabling local privilege escalation to root on specific Android devices (iQOO Neo5/PD2118, kernel 4.19.152-perf+). The repository contains precompiled ARM64 PIE binaries (ghostlock_pd2118, su_daemon_aarch64_pie) deployed via ADB to /data/local/tmp/ for root shell establishment. No evidence of in-the-wild exploitation exists; this is unattributed research code, not observed adversary activity.

### Recommended Hypothesis
> Adversaries use local futex priority-inheritance exploits (CVE-2026-43499) to escalate privileges from unprivileged user to root on vulnerable Linux/Android kernels with affected rtmutex implementations.

### Gaps Identified
- Enterprise EDR/MDM telemetry for Android device kernel exploitation is typically unavailable; detection requires device-level auditd/SELinux logs capturing futex syscalls with PI flags, FUTEX_LOCK_PI/FUTEX_UNLOCK_PI operations, and abnormal rtmutex priority inversions that are rarely forwarded to centralized SIEM.
- ADB push operations to /data/local/tmp/ and subsequent execution of unsigned PIE binaries may occur on developer-authorized devices with USB debugging enabled, making behavioral distinction between legitimate development activity and exploit delivery inconclusive without process ancestry, capability acquisition (CAP_SYS_ADMIN post-exploit), and kernel memory access patterns.
- Kernel-level use-after-free primitives in rtmutex code paths produce no application-layer observables; detection requires kernel tracing (ftrace, eBPF kprobes on rt_mutex_adjust_prio_chain, remove_waiter) to capture stale task_struct dereferences, which is not deployed in typical enterprise mobile device management.

- Focus: Query Linux/Android endpoint logs for execve() of binaries from world-writable temporary paths (/data/local/tmp/, /tmp/, /var/tmp/) followed by setuid(0)/setgid(0) capability changes or uid transitions to root, correlating with prior ADB connections or USB debugging events.
