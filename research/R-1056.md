## 1. System Research: How It Works

### Summary
sevenz-rust2 is a Rust-native library that compresses and decompresses 7z archives. Prior to version 0.21.1, the decompression logic in `src/util/decompress.rs` failed to normalize archive entry names or verify containment, allowing extraction paths to escape the destination directory via parent-directory components or absolute paths.

### Key Findings
- The vulnerability is located in the `decompress_impl` function within `src/util/decompress.rs`, where `dest.join(entry.name())` is used without normalizing UTF-16 entry names or verifying that the resulting path remains within the extraction root.
- Exploitation allows an attacker to write or overwrite files outside the intended destination directory by using parent-directory components (e.g., `../`) or absolute paths in the archive metadata.
- The issue is resolved in sevenz-rust2 version 0.21.1; versions prior to this release are susceptible to improper limitation of a pathname to a restricted directory.
- Public Proof-of-Concept (PoC) material exists in the GitHub repository `pluto-chou/CVE-2026-61725_sevenz-rust2`, which includes Python scripts designed to test vulnerable (`harness_vuln`) and fixed (`harness_fixed`) binaries.

## 5. Research Synthesis

### Executive Summary
A public PoC repository (pluto-chou/CVE-2026-61725_sevenz-rust2) documents a path traversal flaw in sevenz-rust2 prior to v0.21.1, where unsanitized archive entry names passed to `dest.join(entry.name())` permit writes outside the extraction root; OSV.dev corroborates the advisory (GHSA-qh76-45cr-8xrc, CVSS 3.1 AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:H/A:L), while EPSS (0.19%, 4.9th percentile) and absence from VulnCheck KEV indicate low observed exploitation probability at time of writing. No attacker activity has been observed; evidence is limited to a PoC repository and advisory, and conclusions about exploitation in any specific environment are not supported by current telemetry. Hunt focus should target environments where sevenz-rust2 is used to decompress attacker-influenced 7z archives—particularly web services, build pipelines, or file-processing backends—where a traversal write could overwrite binaries, configuration, or web-accessible files to achieve persistence or code execution.

### Recommended Hypothesis
> Adversaries use a maliciously crafted 7z archive containing path-traversal or absolute-path entry names to exploit CVE-2026-61725 in sevenz-rust2 (pre-0.21.1), causing the decompression routine to write or overwrite files outside the intended extraction directory on systems that process attacker-influenced archives, enabling file planting for persistence or code execution without direct shell access.

### Gaps Identified
- File-write telemetry is unlikely to be attributed back to the sevenz-rust2 decompression call chain unless process-level file activity (e.g., Sysmon Event ID 11 with full path, or equivalent eBPF/auditd `openat`/`write` syscall records) is collected for the specific Rust binary or service invoking the library; absent this, traversal writes will appear as ordinary file creation events with no linkage to archive processing, making behavioral correlation infeasible.
- Rust binaries statically linking sevenz-rust2 produce no distinct process name or module load event that distinguishes the vulnerable library version from a patched one at runtime; without a software inventory or SBOM that maps deployed binary hashes to sevenz-rust2 crate versions, it is not possible to enumerate in-scope assets or confirm patch status across the estate.
- The vulnerability is triggered at decompression time by archive metadata (entry name field), which is opaque inside the 7z container and not inspected by most network-layer controls or AV signature engines; without archive-aware content inspection at the point of ingest (e.g., a pre-extraction validation step or sandbox detonation of received archives), malicious entry names will not be detected before the vulnerable code path executes.
