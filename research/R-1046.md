## 1. System Research: How It Works

### Summary
MONAI Label is a datastore system that utilizes specific HTTP endpoints to manage medical imaging data and associated labels. Under normal operation, it accepts uploads via the PUT /datastore/image endpoint, where the 'image' query parameter serves as the identifier for storing files within the designated datastore directory.

### Key Findings
- The PUT /datastore/image endpoint is a primary telemetry signal, accepting a caller-controlled 'image' query parameter that identifies the image ID but previously lacked validation against path traversal sequences.
- Normal file storage relies on joining the 'image' parameter to the datastore directory; however, the vulnerability stems from insufficient sanitization of this parameter before path resolution.
- The system utilizes internal methods such as save_label() and _datastore.label_path() to handle label tags, which are subject to checks ensuring files remain within specific root directories, a mechanism exploited by attackers using traversal sequences like '../../../tmp/x'.
- Network traffic involving the PUT /datastore/label endpoint also contains similar risks, as it shares the same lack of sanitization for caller-controlled parameters in the context of CVE-2026-133968.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploited CVE-2026-133968, a path traversal vulnerability in MONAI Label 0.8.5, to write arbitrary files and achieve remote code execution with root shell access. This exploitation was carried out by China-linked threat actors using autonomous AI agents via the Cairn framework in September 2026.

### Key Findings
- The vulnerability CVE-2026-133968 is a critical path traversal flaw in MONAI Label version 0.8.5 that allows unauthenticated attackers to write files outside the intended datastore directory.
- Threat actors exploited this zero-day vulnerability between September 8–10, 2026, resulting in root shell access on a university server.
- The attack utilized Cairn, an open-source autonomous penetration-testing framework, deployed by suspected China-linked threat actors to discover and exploit the flaw.
- While CVE-2026-133968 affects MONAI Label, a related path traversal vulnerability (CVE-2026-21851) exists in MONAI core versions up to 1.5.1 within the `_download_from_ngc_private()` function during NGC private bundle extraction.

## 5. Research Synthesis

### Executive Summary
CVE-2026-133968 is a path traversal vulnerability in MONAI Label ≤0.8.5 exploited via unauthenticated HTTP PUT requests to /datastore/image and /datastore/label endpoints with traversal sequences in caller-controlled parameters, resulting in arbitrary file write and remote code execution. China-linked actors exploited this zero-day in September 2026 using the Cairn autonomous penetration-testing framework to achieve root shell access on university infrastructure. Detection requires HTTP request inspection, file system monitoring for writes outside datastore boundaries, and correlation of MONAI Label process behavior with unexpected file creation or execution.

### Recommended Hypothesis
> Adversaries use unauthenticated HTTP PUT requests to MONAI Label /datastore/image or /datastore/label endpoints with path traversal sequences (e.g., '../../../tmp/x') in the 'image' parameter to write arbitrary files outside the datastore directory and achieve remote code execution on medical imaging infrastructure.

### Gaps Identified
- HTTP application-layer visibility into MONAI Label API endpoints is required to detect PUT requests with traversal sequences in query parameters; network flow metadata alone cannot identify malicious 'image' parameter values without deep packet inspection or web proxy logging with full URI capture.
- File system telemetry correlating MONAI Label process (or its parent Python interpreter) file write operations to paths outside the configured datastore directory is necessary but may be absent if endpoint detection lacks process-to-file-path correlation or if MONAI Label runs in containerized environments without host-level file activity monitoring.
- Distinguishing between legitimate datastore operations and exploitation requires baseline knowledge of the configured datastore directory path and normal file naming patterns, which may be unavailable if asset inventory lacks application-specific configuration details or if MONAI Label deployments are unknown to the security team.

### Key Findings
- Hypothesis: Adversaries use unauthenticated HTTP PUT requests to MONAI Label /datastore/image or /datastore/label endpoints with path traversal sequences (e.g., '../../../tmp/x') in the 'image' parameter to write arbitrary files outside the datastore directory and achieve remote code execution on medical imaging infrastructure.
- Gap: HTTP application-layer visibility into MONAI Label API endpoints is required to detect PUT requests with traversal sequences in query parameters; network flow metadata alone cannot identify malicious 'image' parameter values without deep packet inspection or web proxy logging with full URI capture.
- Gap: File system telemetry correlating MONAI Label process (or its parent Python interpreter) file write operations to paths outside the configured datastore directory is necessary but may be absent if endpoint detection lacks process-to-file-path correlation or if MONAI Label runs in containerized environments without host-level file activity monitoring.
- Gap: Distinguishing between legitimate datastore operations and exploitation requires baseline knowledge of the configured datastore directory path and normal file naming patterns, which may be unavailable if asset inventory lacks application-specific configuration details or if MONAI Label deployments are unknown to the security team.
- Focus: Query web proxy logs, WAF logs, or HTTP server access logs for PUT requests to URIs matching '/datastore/image' or '/datastore/label' with query parameters containing traversal sequences ('../', '..\', URL-encoded equivalents '%2e%2e%2f', or absolute paths) from unauthenticated sources, prioritizing external or unexpected internal source IPs.
- Focus: Correlate file creation events outside expected datastore directories (typically under application working directories) with parent processes matching MONAI Label's Python runtime (e.g., 'python', 'uvicorn', 'gunicorn') or containerized workloads labeled as MONAI Label, focusing on sensitive paths like /tmp, /var/tmp, web roots, or cron/systemd directories that enable persistence or execution.
- Focus: Identify MONAI Label deployments in the environment through asset discovery (listening services on typical ports, container image names containing 'monai', or application inventory), verify versions ≤0.8.5, assess internet exposure, and establish file system baselines for datastore boundaries to enable anomaly detection for out-of-bounds file writes.
