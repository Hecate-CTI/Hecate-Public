## 1. System Research: How It Works

### Summary
Perforce Puppet Enterprise manages infrastructure configuration by having agents submit JSON reports to the server after each run. This process involves the deserialization of untrusted data within the report-processing code, which is exploited via crafted rich-data types submitted through PUT requests.

### Key Findings
- The vulnerability resides in the report-processing code where Puppet Server deserializes data sent from agents, specifically targeting rich-data types within the submitted reports.
- Exploitation occurs when an agent submits a crafted report containing malicious rich-data via a PUT request, allowing arbitrary code execution on the Puppet Server as the service user.
- Access to exploit this vulnerability requires a client certificate signed by the Puppet Certificate Authority; exploitation is facilitated if the CA automatically signs requests without strong verification.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit CVE-2026-115731 by submitting crafted HTTP PUT requests containing malicious rich-data types to Perforce Puppet Enterprise's report-processing code, triggering arbitrary code execution on the server. If the internal Certificate Authority lacks strong verification controls, unauthenticated attackers can obtain valid CA-signed agent certificates to bypass authentication and initiate this exploitation.

### Key Findings
- The vulnerability (CVE-2026-115731) allows remote code execution as the service user via deserialization of untrusted data in Puppet’s report-processing module.
- Exploitation requires a CA-signed agent certificate, but if the Certificate Authority automatically signs requests without strong verification, an unauthenticated network attacker can obtain valid credentials to exploit the flaw.
- The attack vector specifically involves submitting a crafted rich-data type through an HTTP PUT request to trigger the deserialization flaw.
- CISA added this vulnerability to its Known Exploited Vulnerabilities (KEV) catalog on November 17, 2026, indicating active exploitation in the wild.
- The affected versions include Puppet Enterprise 2026.0.0 before 2026.0.1, 2025.0.0 before 2025.12.1, and 2023.8.0 before 2023.8.13.
- The vulnerability carries a high severity score (CVSS 9.4 in CISA data, 9.9 in NVD), highlighting significant risk to enterprise management servers.

## 5. Research Synthesis

### Executive Summary
CVE-2026-115731 is a known-exploited deserialization vulnerability in Puppet Enterprise's report-processing code, allowing arbitrary code execution via crafted rich-data types in HTTP PUT requests from clients possessing CA-signed agent certificates. Detection requires visibility into Puppet Server HTTP request payloads, certificate issuance patterns, and post-exploitation behaviors, as the deserialization occurs server-side during report ingestion. The vulnerability is actively exploited per CISA KEV (added 2026-11-17), with exploitation trivial when certificate authorities lack strong verification controls.

### Recommended Hypothesis
> Adversaries use crafted rich-data types in HTTP PUT requests to Puppet Server's report endpoint to achieve arbitrary code execution as the Puppet service user on Puppet Enterprise servers

### Gaps Identified
- Puppet Server HTTP request body inspection and deserialization event logging may be unavailable or insufficient to distinguish malicious rich-data payloads from legitimate agent reports without deep packet inspection or application-layer telemetry from the Puppet Server process itself
- Certificate Authority signing activity and agent certificate issuance telemetry may not be collected or correlated with subsequent report submissions, preventing detection of unauthorized certificate acquisition followed by exploitation attempts
- Post-exploitation behavior of the Puppet service user account may blend with legitimate configuration management activities, requiring behavioral baselining of process creation, network connections, and file operations initiated by the Puppet Server service account that are atypical for report processing

### Key Findings
- Hypothesis: Adversaries use crafted rich-data types in HTTP PUT requests to Puppet Server's report endpoint to achieve arbitrary code execution as the Puppet service user on Puppet Enterprise servers
- Gap: Puppet Server HTTP request body inspection and deserialization event logging may be unavailable or insufficient to distinguish malicious rich-data payloads from legitimate agent reports without deep packet inspection or application-layer telemetry from the Puppet Server process itself
- Gap: Certificate Authority signing activity and agent certificate issuance telemetry may not be collected or correlated with subsequent report submissions, preventing detection of unauthorized certificate acquisition followed by exploitation attempts
- Gap: Post-exploitation behavior of the Puppet service user account may blend with legitimate configuration management activities, requiring behavioral baselining of process creation, network connections, and file operations initiated by the Puppet Server service account that are atypical for report processing
- Focus: Identify HTTP PUT requests to Puppet Server report endpoints (typically /puppet/v3/report/) containing rich-data type structures in request bodies, correlating with Puppet Server process behavior anomalies (unexpected child processes, network connections, or file writes by the service user)
- Focus: Enumerate all Puppet Enterprise server instances and their certificate authority configurations to determine exposure scope, then validate availability of Puppet Server access logs, application logs with deserialization events, and host-based telemetry from servers running the Puppet Server service
- Focus: Baseline normal Puppet service user behavior (process ancestry, network destinations, file system activity) to detect post-exploitation actions such as spawning interactive shells, executing system utilities, or establishing outbound connections to non-Puppet infrastructure
