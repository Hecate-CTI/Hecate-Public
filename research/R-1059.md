## 1. System Research: How It Works

### Summary
Drupal Core functions as a web content management system that utilizes a database abstraction API, specifically supporting PostgreSQL backends, to manage data. The JSON:API module provides a zero-configuration, opinionated RESTful interface for performing CRUD operations on Drupal entities, allowing clients to interact with the system via HTTP requests.

### Key Findings
- The vulnerability resides in the improper neutralization of attacker-controlled input within the filter parameter keys of the JSON: API module's database abstraction layer.
- Exploitation is possible without authentication, session tokens, or prior footholds, allowing unauthenticated remote attackers to inject arbitrary SQL commands via specially crafted HTTP requests.
- The affected systems involve PostgreSQL backends processed through Drupal Core versions 8.9.0 through 11.3.x, indicating a broad impact across multiple release lines.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are actively exploiting CVE-2026-9082, a critical pre-authentication SQL injection vulnerability in Drupal Core's JSON:API module, to gain unauthorized read and write access to the database. Exploitation occurs via filter condition parameters in endpoints like /jsonapi/node/{type}, requiring no authentication and allowing for rapid initial access and data exfiltration within days of disclosure.

### Key Findings
- CVE-2026-9082 is a critical SQL injection vulnerability in Drupal Core (versions 8.9.0 through 11.x branches) affecting the JSON:API module, allowing exploitation without authentication.
- The vulnerability was added to the CISA Known Exploited Vulnerabilities (KEV) catalog on May 22, 2026, with a remediation deadline of May 27, just two days after its publication on May 20, 2026.
- Adversaries are systematically probing /jsonapi/node/{type} endpoints to exploit the vulnerability, with confirmed in-the-wild exploitation observed as early as May 21, 2026.
- Successful exploitation grants attackers read and write access to the Drupal database, enabling the exfiltration of session tokens, password hashes, and potentially leading to remote code execution if PostgreSQL has elevated privileges.

## 5. Research Synthesis

### Executive Summary
CVE-2026-9082 is a pre-authentication SQL injection in Drupal Core's JSON:API module (versions 8.9.0–11.3.x on PostgreSQL backends), actively exploited in-the-wild as early as May 21, 2026 and confirmed in VulnCheck KEV; exploitation requires no credentials and targets filter condition parameters in /jsonapi/node/{type} endpoints, enabling direct database read/write and potential RCE if the PostgreSQL process holds elevated OS privileges. EPSS scores this at the 97.5th percentile (15.70%) and OSV.dev rates it highly critical (CVSS 3.1: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H), while OTX pulse association with INC Ransom and The Gentlemen ransomware groups suggests post-exploitation objectives may extend to ransomware staging. Hunt focus must distinguish systematic /jsonapi probing and anomalous SQL error patterns from legitimate API traffic before asserting exploitation success or actor attribution.

### Recommended Hypothesis
> Adversaries use unauthenticated HTTP requests with malformed filter condition parameters against Drupal JSON:API endpoints (/jsonapi/node/{type}) to inject arbitrary SQL commands into PostgreSQL backends, achieving unauthorized database read/write access and potentially escalating to remote code execution on Drupal Core instances running versions 8.9.0 through 11.3.x (T1190)

### Gaps Identified
- Web application layer payloads are typically not reconstructed from raw packet captures in most SIEM/EDR pipelines — if TLS termination occurs at a load balancer or CDN without full request body logging forwarded downstream, the malicious filter parameter key content will be invisible to host-based telemetry, making payload-level detection of the SQLi string impossible without WAF or reverse-proxy access logs that capture full query strings and POST bodies with sufficient field length (many log configs truncate URI parameters)
- PostgreSQL-level query telemetry (pg_audit extension or equivalent statement-level logging) is frequently absent or not ingested into the SIEM, meaning that even if the HTTP request is logged, the resulting injected SQL execution — including SELECT on session/password hash tables or COPY TO for data exfiltration — will not be observable as a discrete event; without database audit logs correlated to the web tier, process access and query execution cannot be separated from inferred exploitation success
- The JSON:API module is a zero-configuration interface enabled by default in Drupal 8.9+, meaning asset inventory may not reliably distinguish which Drupal instances expose this endpoint externally versus internally, and version-level patch state for Drupal Core across the 8.9.0–11.3.x range is unlikely to be uniformly tracked in CMDB or vulnerability scan data — scope of exposed, unpatched attack surface cannot be bounded without verified, current scan coverage against the full web-server estate

- Focus: Hunt for anomalous HTTP request patterns against /jsonapi/ URI paths — specifically requests where filter parameter keys contain SQL metacharacters (quotes, comment sequences, UNION/SELECT keywords) or unusually high key-count arrays; baseline legitimate JSON:API filter key structure from known application behavior and flag structural deviations; correlate source IPs across multiple Drupal hosts to identify systematic scanning consistent with adversary reconnaissance observed as early as May 21, 2026
