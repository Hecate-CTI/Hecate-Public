## 1. System Research: How It Works

### Summary
ClickFix is a social engineering attack that deceives users into pasting malicious shell scripts into the macOS Terminal by mimicking CAPTCHA verification prompts. These scripts act as loaders that profile the system architecture and download a Go-based Mach-O payload designed to steal credentials and drain cryptocurrency wallets.

### Key Findings
- The infection vector relies on social engineering where fake CAPTCHA pop-ups instruct users to copy and execute long command strings in the macOS Terminal, bypassing traditional security controls by leveraging legitimate system utilities like curl.
- The delivered malware is a Go-compiled Mach-O executable tailored to the victim's specific CPU architecture, which functions as a stealer scraping browser password stores, Apple Keychain data, and cached credentials.
- A critical capability of the payload includes a 'DRAIN' function that monitors cryptocurrency wallets for funds and redirects balances to attacker-controlled addresses.
- Infrastructure supporting the loader, payload hosting, and command-and-control (C2) is tied to Aeza Group, a Russian bulletproof hosting provider sanctioned by the US, UK, and Australia in 2025.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries utilize the ClickFix technique to deceive macOS users into manually executing malicious shell scripts via Terminal by presenting fake CAPTCHA prompts that mimic legitimate verification steps. This method bypasses traditional browser security controls, allowing attackers to deliver loader scripts that deploy native Mach-O malware designed to steal credentials and drain cryptocurrency wallets.

### Key Findings
- The attack relies on social engineering where users are tricked into pasting a long command string from a fake CAPTCHA popup into the macOS Terminal application.
- The delivered payload is a Go-based Mach-O executable that scrapes browser password stores, Apple Keychain data, and cached credentials for exfiltration.
- A specific capability of the malware includes a 'DRAIN' function that checks cryptocurrency wallet balances and redirects funds to attacker-controlled accounts.
- Infrastructure used for delivery and command-and-control is linked to Aeza Group, a Russian bulletproof hosting provider sanctioned by the US, UK, and Australia in 2025.
- The loader script performs system profiling to identify the victim's CPU architecture before fetching the appropriate native malware payload.

## 5. Research Synthesis

### Executive Summary
ClickFix attacks on macOS bypass traditional security controls by exploiting user execution of malicious shell commands via Terminal, delivering architecture-specific Go-based Mach-O stealers that persist through LaunchAgents and BTM subsystem abuse. The malware removes Gatekeeper quarantine attributes, scrapes Keychain and browser credential stores, and implements cryptocurrency wallet draining via blockchain queries and transaction redirection. Infrastructure ties to Aeza Group (AS210644) sanctioned bulletproof hosting, with C2 communication over non-standard ports (8133/tcp).

### Recommended Hypothesis
> Adversaries use ClickFix social engineering to trick macOS users into manually executing Terminal commands that download architecture-specific Mach-O payloads, which then persist via LaunchAgents, remove Gatekeeper quarantine attributes, scrape credentials from Keychain and browsers, and drain cryptocurrency wallets by querying blockchain balances and redirecting transactions to attacker-controlled addresses.

### Gaps Identified
- Detection of xattr -d com.apple.quarantine execution may be incomplete if process creation telemetry does not capture full command-line arguments showing the specific extended attribute removal targeting downloaded payloads in non-standard directories like ~/Library/Caches/com.apple.trustd/
- Identification of osascript-based credential prompting abuse requires correlation between osascript process creation with dialog parameters requesting authentication and subsequent privilege escalation actions, which may not be captured if macOS Unified Logs or EDR telemetry lacks osascript argument parsing
- Detection of cryptocurrency wallet draining behavior requires visibility into outbound blockchain API queries (e.g., balance checks via HTTP/HTTPS to public blockchain explorers) correlated with wallet file access and subsequent network connections to non-standard C2 ports, which may be incomplete without TLS inspection or application-layer protocol analysis

### Key Findings

- Gap: Identification of osascript-based credential prompting abuse requires correlation between osascript process creation with dialog parameters requesting authentication and subsequent privilege escalation actions, which may not be captured if macOS Unified Logs or EDR telemetry lacks osascript argument parsing

- Focus: Hunt for Terminal (bash/zsh) process creation events with command-line patterns containing curl piped to bash execution, history deletion commands (history -d, fc -p /dev/null), and Terminal clearing sequences (printf '\033[3J'), particularly when writing to /tmp or ~/Library/Caches/ directories with randomized filenames
- Focus: Identify launchctl bootstrap commands enrolling LaunchAgents from user-writable paths (~/Library/LaunchAgents/) combined with xattr removal on Mach-O executables in non-standard cache directories (e.g., com.apple.trustd, com.apple.softwareupdate) that mimic legitimate Apple system process names
- Focus: Detect access to macOS Keychain databases (~/Library/Keychains/), browser credential stores (Chrome/Firefox/Safari Login Data, Cookies files), and cryptocurrency wallet files (.wallet, wallet.dat) followed by network connections to Aeza Group ASN (AS210644) infrastructure or non-standard high ports (8000-9000 range) over HTTP protocol
