## 1. System Research: How It Works

### Summary
FreeSWITCH processes inbound SIP MESSAGE requests via the `mod_sofia` module, specifically through the `sofia_presence_handle_sip_i_message()` function which parses the 'To' header to select chat protocols. Under normal operation, this parsing logic handles standard text chat interactions without executing arbitrary system commands, but a vulnerability in versions 1.11.2 and earlier allows unauthenticated command injection by manipulating the protocol selection.

### Key Findings
- The vulnerability stems from `sofia_presence_handle_sip_i_message()` splitting the 'To' user on the '+' character to select the chat protocol, which triggers `switch_api_execute()` for arbitrary command execution when manipulated via a SIP MESSAGE.
- Exploitation requires sending a specially crafted SIP MESSAGE that selects the 'api' chat protocol, allowing an attacker to run FreeSWITCH API and OS commands with the privileges of the FreeSWITCH daemon without authentication.
- The vulnerability affects FreeSWITCH versions 1.11.2 and earlier, with the fix released in version 1.11.3; mitigations include upgrading, disabling inbound chat, restricting SIP MESSAGE access, and removing directory users without passwords.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit CVE-2026-116779 by sending a crafted SIP MESSAGE to FreeSWITCH servers, leveraging an unauthenticated command injection vulnerability in the 'api' chat protocol to execute arbitrary OS commands. This technique allows attackers to gain remote code execution, disclose credentials, and control calls on vulnerable versions prior to 1.11.3.

### Key Findings
- The vulnerability is an unauthenticated command injection in FreeSWITCH (versions < 1.11.3) where a SIP MESSAGE can select the 'api' chat protocol to execute server-side commands.
- Exploitation has been observed in the wild, with attackers using the flaw for remote code execution, credential disclosure, and call control.
- FreeSWITCH version 1.11.3 includes a mitigation gate that returns HTTP 403 responses to blocked attempts, effectively patching the issue.
- Public Proof-of-Concept tools like 'SIP2Shell' and 'freeswitch-cve-2026-116779-POC' provide capabilities for detection, API execution, reverse shells, and out-of-band (OOB) data exfiltration.
- Detection indicators include monitoring for HTTP 403 responses on SIP MESSAGE endpoints and verifying FreeSWITCH version numbers against the 1.11.3 threshold.

## 5. Research Synthesis

### Executive Summary
CVE-2026-116779 is an unauthenticated command injection vulnerability in FreeSWITCH ≤1.11.2 where crafted SIP MESSAGE packets selecting the 'api' chat protocol enable arbitrary OS command execution via `switch_api_execute()`. VulnCheck reports active in-the-wild exploitation, but the source intelligence is a public PoC repository (DeathShotXD/SIP2Shell) with no verified adversary activity in workspace scope. Detection requires SIP protocol visibility, application-layer payload inspection of MESSAGE requests, and correlation of FreeSWITCH process behavior with network events—capabilities not validated in the current telemetry inventory.

### Recommended Hypothesis
> Adversaries send crafted SIP MESSAGE packets with 'To' headers containing 'api+' protocol selectors to FreeSWITCH servers (ports 5060/5061 UDP/TCP) to execute OS commands via unauthenticated command injection, enabling reconnaissance, credential theft, and persistence on vulnerable instances ≤1.11.2.

### Gaps Identified
- SIP application-layer payload inspection capability is unverified—detection requires visibility into SIP MESSAGE method 'To' header contents (specifically 'api+' protocol strings) and the ability to correlate SIP packets with FreeSWITCH process execution events (e.g., `switch_api_execute()` invocations, child process spawning) which may not be captured by standard network flow logs or endpoint telemetry without deep packet inspection and process auditing.
- FreeSWITCH application logging configuration and ingestion status is unknown—successful exploitation may only be visible in FreeSWITCH's own logs (e.g., sofia.c debug output, API command execution logs) rather than OS-level process creation events, and the workspace has not confirmed whether these application logs are collected, parsed, or retained for correlation with network indicators.
- Out-of-band (OOB) data exfiltration channels are difficult to detect without HTTP/DNS request payload inspection—the PoC demonstrates command output retrieval via attacker-controlled HTTP listeners (port 8899, path /1fx5n6 in examples), but detection requires correlating FreeSWITCH process network connections to unusual external HTTP endpoints, which may be obscured by legitimate SIP trunk traffic or missing if only NetFlow/connection metadata is available without full packet capture or HTTP request logging.
