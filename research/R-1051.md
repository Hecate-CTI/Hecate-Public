## 1. System Research: How It Works

### Summary
MISP exports Network Intrusion Detection System (NIDS) rules for Snort and Suricata, a process that previously failed to properly escape user-controlled data in attribute values and tags. This improper encoding allows raw URL paths containing semicolons to be injected into the rule configuration, potentially enabling rule injection attacks rather than simple host output.

### Key Findings
- The vulnerability resides in the 'NIDS Export (Snort)' and 'NIDS Export (Suricata)' modules, specifically within the files app/Lib/Export/NidsExport.php and app/Lib/Export/NidsSuricataExport.php.
- The issue is classified as CWE-116 (Improper Encoding or Escaping of Output) under OWASP Top 10 A05:2025 Injection, with a MEDIUM severity CVSS v3.1 score of 5.3/10.
- Affected systems are MISP versions prior to 2.5.52; the fix involves ensuring raw data is properly escaped during export rather than passed verbatim.
- The vulnerability has an estimated EPSS exploitation probability of 8.21%, indicating a moderate likelihood of exploitation in the wild.

## 5. Research Synthesis

### Executive Summary
A public PoC repository (googlesky/CVE-2026-135253) documents a rule-injection flaw in MISP versions prior to 2.5.52 (CWE-116), where unescaped semicolons in user-controlled URL path data are passed verbatim into Suricata/Snort NIDS export output, enabling injection of attacker-controlled logic into network defense rule sets. The vulnerability is classified CVSS v3.1 5.3 Medium with low attack complexity and requires only low privileges and no user interaction (OSV.dev advisory); EPSS figures are inconsistent between sources (0.41% from enrichment feed vs. 8.21% from system research) and should not be treated as calibrated probabilities. No exploitation in the wild has been observed within tested scope, and the PoC's functional effectiveness has not been independently verified; the GTFOBins/LOLBAS references in secondary enrichment are not relevant to this Linux/Python/PHP attack surface and are noted as noise.

### Recommended Hypothesis
> Adversaries use crafted HTTP requests containing semicolon-delimited URL path segments submitted to MISP's NIDS export endpoint to inject malicious Suricata or Snort rule logic into exported rule files on MISP instances running versions prior to 2.5.52, with the goal of corrupting or subverting the network detection posture of downstream NIDS consumers who import those rules.

### Gaps Identified
- MISP application-layer telemetry covering the NIDS export endpoint (POST /events/nids/suricata or equivalent) is unlikely to be ingested into a SIEM by default; without HTTP request body or URL path logging from the MISP web server (e.g., Apache/nginx access logs with full request URI, or MISP audit logs capturing export parameters), semicolon-injected host values will not be observable, making the injection event itself a blind spot regardless of endpoint monitoring coverage.
- The injected payload lands inside an exported rule file rather than producing a process execution or network connection on the MISP host itself; detection therefore requires integrity monitoring of exported Suricata/Snort rule artifacts (e.g., file hash comparison, rule-syntax validation in CI/CD or rule-distribution pipelines) rather than conventional EDR or auth telemetry — a control that is rarely deployed and whose coverage in the target environment is unverified.
- The vulnerability requires a low-privilege authenticated MISP session; without correlation between MISP user authentication logs (login events tied to specific accounts) and subsequent NIDS export requests, it is not possible to determine whether an export anomaly originates from a compromised account, an insider, or an authorized user, leaving attribution and triage severely limited.

### Key Findings
- Hypothesis: Adversaries use crafted HTTP requests containing semicolon-delimited URL path segments submitted to MISP's NIDS export endpoint to inject malicious Suricata or Snort rule logic into exported rule files on MISP instances running versions prior to 2.5.52, with the goal of corrupting or subverting the network detection posture of downstream NIDS consumers who import those rules.
- Gap: MISP application-layer telemetry covering the NIDS export endpoint (POST /events/nids/suricata or equivalent) is unlikely to be ingested into a SIEM by default; without HTTP request body or URL path logging from the MISP web server (e.g., Apache/nginx access logs with full request URI, or MISP audit logs capturing export parameters), semicolon-injected host values will not be observable, making the injection event itself a blind spot regardless of endpoint monitoring coverage.
- Gap: The injected payload lands inside an exported rule file rather than producing a process execution or network connection on the MISP host itself; detection therefore requires integrity monitoring of exported Suricata/Snort rule artifacts (e.g., file hash comparison, rule-syntax validation in CI/CD or rule-distribution pipelines) rather than conventional EDR or auth telemetry — a control that is rarely deployed and whose coverage in the target environment is unverified.
- Gap: The vulnerability requires a low-privilege authenticated MISP session; without correlation between MISP user authentication logs (login events tied to specific accounts) and subsequent NIDS export requests, it is not possible to determine whether an export anomaly originates from a compromised account, an insider, or an authorized user, leaving attribution and triage severely limited.
- Focus: Hunt for anomalous MISP NIDS export requests by parsing MISP or web-server access logs for export endpoint calls (e.g., paths matching /events/nids/) where the host parameter or URL path contains semicolons, percent-encoded semicolons (%3B), or other Suricata rule-grammar metacharacters; correlate by source IP and authenticated user account to identify low-frequency, outlier requestors.
- Focus: Inspect exported Suricata/Snort rule files distributed from MISP for syntactic anomalies — specifically rule fields (msg, content, http.uri, metadata) containing unexpected semicolons, option-block separators in non-standard positions, or duplicate/injected rule options — by diffing current exports against a known-good baseline or running exported rules through a rule-parser (e.g., suricata --list-runmodes or idstools) to surface parse errors indicative of injection.
- Focus: Verify MISP version inventory across the estate to determine exposure scope; instances confirmed at version 2.5.52 or later are patched per the advisory, but version telemetry must come from an authoritative CMDB or package manager query rather than assumed — unverified version data cannot bound exposure, and instances discovered below the threshold should be prioritized for export-log review before patch confirmation.
